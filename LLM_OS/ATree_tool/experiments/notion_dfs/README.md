# Notion DFS Experiments

This directory contains experiments and output data related to extracting the full accessibility tree of Notion (an Electron app).

## The Challenge

Electron apps like Notion heavily truncate their accessibility tree by default to save memory. A standard `agent-desktop snapshot` only returns a shallow "skeleton" of the UI, hiding all inner content (buttons, text, etc.) behind a `children_count` property without exposing the actual child nodes.

## The Solution: DFS Drill-Down

To get the full tree, we must recursively drill down into truncated nodes using `agent-desktop snapshot --root <ref_id>`. 

Our script (`../../tasks/click_notion_library.js`) performs this DFS in-memory.

## Key Learnings & Pitfalls

1. **Avoid `--skeleton` and `--compact`:** These flags strip `ref_id`s from child nodes, making it impossible to drill down further (`INVALID_ARGS` error). Always use a full snapshot (`-i --include-bounds`).
2. **Hidden Ghost Windows:** Notion spawns multiple background windows (all titled "Notion" and mostly `visible: false`). Snapshotting these times out. Always filter for the real window (usually `visible: true` and `is_focused: true` with a meaningful title like the current page name).
3. **The Offscreen Trap:** Many nodes exist in the DOM but are scrolled out of view. They will have `bounds.height: 0` and `"offscreen"` in their `states`. Clicking these coordinates hits thin air.
    - **Fix:** Check for the `ScrollTo` action. Run `agent-desktop scroll-to <ref_id>`, wait for the animation, then take a *new* snapshot and run DFS again to get the updated, non-zero bounds before clicking.
4. **Single JSON Output:** Instead of saving many small JSON files per drill-down, it is much cleaner to expand the tree in-memory and save one final, complete `notion_full_tree.json`. This makes searching (e.g., via `grep` or `python`) much easier.

## Contents

- `notion_full_tree.json`: The final, fully expanded accessibility tree generated by the DFS script. (Overwritten on each run).
